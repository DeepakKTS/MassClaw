Data Flow: Task Submission → Result

POST /workflows/submit { instruction, budget } │ ▼ GoalInterpreter → StructuredGoal (intent, risk, complexity) │ ▼ AdaptivePlanner → ExecutionMode (direct | dag | iterative | verify | explore) │ ▼ StrategyRouter → dispatches to chosen strategy │ ▼ (for DAG_PIPELINE) TaskDecomposer → DAG with N tasks + dependencies │ ▼ AgentSelector → best agent per task (trust × cost × latency × capability) │ ▼ WorkflowScheduler: ├─ Check semantic cache (hit? → instant result) ├─ Reserve budget (atomic, row-level lock) ├─ Execute in parallel (Haiku for simple, Sonnet for complex) ├─ Write results to shared memory ├─ Update trust scores └─ Publish SSE progress events │ ▼ OutputSynthesizer → combined result with confidence │ ▼ Workflow.status = COMPLETED, result stored

Quick Deploy

# 1. Infrastructure
docker compose -f docker/docker-compose.yml up -d postgres redis

# 2. Backend
cd backend
pip install -e ".[dev]"
alembic upgrade head
python ../scripts/seed_agents.py
uvicorn app.main:app --port 8000

# 3. Frontend (optional)
cd frontend && npm install && npm run dev

# 4. Verify
curl http://localhost:8000/ready
curl http://localhost:8000/api/v1/capabilities

Primary Demo: Healthcare Operations Analysis

# Step 1: Discover
curl http://localhost:8000/api/v1/capabilities

# Step 2: Submit
curl -X POST http://localhost:8000/api/v1/workflows/submit \
  -H "Content-Type: application/json" \
  -d '{
    "instruction": "Analyze outpatient scheduling bottlenecks, identify staffing inefficiencies, propose improvements, and generate an executive brief",
    "budget": 400,
    "domain": "healthcare"
  }'

# Step 3: Poll (save workflow_id from step 2)
curl http://localhost:8000/api/v1/workflows/{id}/status

# Step 4: Get result (when status=completed)
curl http://localhost:8000/api/v1/workflows/{id}

# Step 5: Check tasks
curl http://localhost:8000/api/v1/tasks/workflow/{id}

Why MassClaw Wins

  • Working software — 83 routes, 12K+ LOC backend, real LLM calls, real orchestration
  • Stock agent compatible — discover → submit → poll → result, zero glue code
  • Enterprise-grade — Bayesian trust, 3-layer safety, audit trails, budget controls
  • Self-improving — agents evolve based on performance, bad ones fade
  • Fast — tiered models (Haiku for simple, Sonnet for complex), semantic caching
  • Simple adoption — pip install + uvicorn + one cURL = working demo
  • Open source — MIT license, clean module boundaries, contributor-friendly

OpenClaw Requirement

The hackathon tests whether a stock OpenClaw-level agent can use what we built. MassClaw passes this by exposing:

  • GET /api/v1/capabilities — machine-readable discovery
  • POST /api/v1/workflows/submit — plain-English instruction in, workflow_id out
  • GET /api/v1/workflows/{id}/status — structured progress polling
  • GET /api/v1/workflows/{id}/result — structured result retrieval
  • Clear docs at docs/openclaw_integration.md
